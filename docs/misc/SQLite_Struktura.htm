SQLite - Struktura hlavních částí databáze

1) Co je to SQLite

SQLite je vestavěný relační databázový engine (embedded database engine), který ukládá data přímo do jednoho souboru. Na rozdíl od klient-server databází nevyžaduje samostatný serverový proces; aplikace komunikuje přímo s knihovnou SQLite.

2) Bloková struktura od nejjednodušší k složitější

2.1 Databázový soubor a stránky (pages)

  • Databáze je rozdělena na stránky pevné velikosti (typicky 4096 B, ale možné jsou i jiné velikosti).
  • Prvních 100 bajtů první stránky tvoří databázovou hlavičku (database header) s metadaty.
  • Základní „blok" práce SQLite je stránka; čtení i zápis probíhá po stránkách.

2.2 Typy stránek v databázovém souboru

  • B-tree stránky (tabulky/indexy): nesou vlastní data a indexové struktury.
  • Freelist trunk/leaf stránky: evidují volné stránky připravené pro opětovné použití.
  • Overflow stránky: uchovávají pokračování dlouhých záznamů, které se nevešly do B-tree buňky.
  • Pointer-map stránky: používají se hlavně v režimu auto-vacuum/incremental-vacuum.
  • Lock-byte page: speciální stránka relevantní pro určité režimy/rozhraní.

2.3 B-tree stránka: vnitřní členění

  • Každá B-tree stránka má hlavičku stránky.
  • Následuje pole ukazatelů na buňky (cell pointer array).
  • Buňky obsahují klíče, payload (data záznamu) a případně odkaz na overflow stránku.
  • Uvnitř stránky je také volné místo, které se využívá při insert/update operacích.

2.4 Buňky, záznamy a serializace hodnot

  • V tabulkovém B-tree listu odpovídá buňka obvykle jednomu řádku.
  • Záznam používá vlastní formát hlavičky + hodnot (serial types), takže různé datové typy mají kompaktní uložení.
  • V indexovém B-tree bývají klíče a reference navržené pro rychlé vyhledávání a třídění.

2.5 Overflow řetězení (větší payload)

  • Když je payload příliš velký, část zůstane v původní B-tree buňce a zbytek se přesune do overflow stránek.
  • Overflow stránky tvoří propojený seznam (linked list).
  • Tento mechanismus umožňuje ukládat i velmi dlouhé hodnoty bez porušení velikosti stránky.

2.6 Freelist a recyklace místa

  • Smazaná/uvoľněná místa nemusí SQLite hned zmenšit na úrovni souboru.
  • Místo toho se stránky ukládají do freelistu a znovu se použijí při dalších operacích.
  • Pro fyzické zmenšení souboru se typicky používá VACUUM (podle režimu databáze).

2.7 Žurnálování a konzistence (rollback journal / WAL)

  • Konzistence transakcí je zajištěna žurnálovacím režimem.
  • Rollback journal: před změnou se ukládá původní stav stránek.
  • WAL (Write-Ahead Logging): změny se nejprve zapisují do WAL souboru, následně checkpoint do hlavního souboru.
  • Volba režimu ovlivňuje výkon zápisu, souběh čtení/zápisu i provozní chování.

2.8 Logická vrstva nad bloky

  • SQL dotazy procházejí parserem a plánovačem.
  • Virtuální stroj (VDBE) provádí instrukce nad B-tree/pager vrstvou.
  • Nízká vrstva pageru mapuje logické operace na fyzické čtení/zápis stránek.
